# Course Reflection: Web Foundations & Systems Design

The most challenging concept in this course was mastering concurrency control and race condition prevention in distributed architectures. Moving beyond basic CRUD operations to understand how database isolation levels, row-level locks, and distributed in-memory caches interact under heavy traffic surges initially felt complex. I overcame this challenge by systematically diagramming end-to-end request lifecycles, calculating quantitative throughput models, and writing atomic SQL statements with strict relational constraints to guarantee bulletproof ACID compliance.

Based on the feedback I received on my QuickNotes capstone project, the primary area I would improve is real-time synchronization and distributed conflict resolution. While the original application handled local persistence, defensive input validation, and secure DOM rendering effectively, it lacked robust support for multi-device concurrent edits. To improve it, I would introduce WebSocket connections for instantaneous bi-directional updates, implement optimistic concurrency control with incremental version numbers, and leverage an asynchronous message queue to process background sync tasks reliably without blocking the client interface.

Next, I plan to delve into advanced distributed systems engineering and cloud infrastructure. Specifically, I want to master event-driven microservices using Apache Kafka for high-throughput message streaming, study distributed consensus algorithms like Raft and Paxos, and gain hands-on experience orchestrating containerized services with Docker and Kubernetes. Applying these architectural paradigms will prepare me to design resilient, enterprise-grade cloud platforms capable of seamlessly scaling to millions of concurrent users.
